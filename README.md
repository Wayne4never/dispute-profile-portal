# OpenTrace — 国内公司与相关人物公开纠纷检索

目标不是只查询某一家教育公司，而是做成一个面向中国大陆公开信息的通用实体调查工具。

## 输入
- 任意中国公司全称 / 曾用名 / 品牌名
- 任意公开职业人物姓名 / 英文名
- 统一社会信用代码
- 法定代表人 / 股东 / 高管姓名
- 案号

## 输出
1. 实体消歧：同名公司、同名人物不自动合并。
2. 公司基础信息：名称、历史名称、法定代表人、股东/高管、地址变更等公开工商信息。
3. 司法纠纷：裁判文书、开庭公告、执行、限制高消费、破产/清算等公开记录。
4. 行政与经营风险：行政处罚、经营异常、欠税等公开记录。
5. 新闻与历史网页：公司官网、媒体报道、公众号/活动页、招聘页、历史网页。
6. 关系图：人物—公司—案件—其他人物之间的公开关系。
7. 时间线：公司和人物关键公开事件按日期排序。
8. 证据型画像：只根据可追溯公开行为证据总结角色、权限、沟通方式、决策特点和风险信号。

## 证据规则
- 事实：有原始来源直接支持。
- 推断：由多个事实综合得出，必须显示推断依据和置信度。
- 主观评价：只能说明“某来源中的某人曾这样评价”，不得自动升级为事实。
- 未核实指控：如“跑路、诈骗、卷款、失联”等，没有可靠来源不得标记为事实。
- 不收集身份证号、家庭住址、私人手机号、实时位置等非必要个人隐私。

## 全国检索的数据层
真正做到“输入任何公司或相关人物就自动查”，需要后端聚合搜索与数据源，GitHub Pages 本身只能承担前端。

建议数据源分层：
- A级：国家企业信用信息公示系统、法院/政府官网、裁判文书、执行公开等官方来源。
- B级：主流媒体、公司官网、交易所/协会等机构来源。
- C级：企业信息聚合平台、招聘与活动历史页等辅助来源。
- D级：论坛/社交平台，仅作为线索，不直接作为事实结论。

## 技术结构
Frontend (GitHub Pages)
→ Search API / Serverless Backend
→ Web Search + 企业数据 API + 司法公开网页
→ Entity Resolution
→ Evidence Extraction
→ Knowledge Graph
→ Evidence-based Profile

当前仓库会按这个“全国通用”方向开发，不把 Joffre/求府写死在程序逻辑里；它只保留为测试样例之一。
